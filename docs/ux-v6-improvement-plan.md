## 1. สิ่งที่ทำดีแล้ว (ไม่ต้องแก้)

## 2. ปัญหาที่พบจากการตรวจโค้ด

### 2.1 ความปลอดภัย — คำยืนยันสั้น (P0)

**Incident จริง:** ผู้ใช้พิมพ์ "ปิดงานทั้งหมด" → ระบบถามยืนยัน → ตอบ "ยืนยัน" → ระบบไปยอม RSVP ประชุมเก่าใน Outlook แทนที่จะปิดงาน

**สาเหตุ:** handler RSVP/reschedule รันก่อน command pipeline และ `getPendingRsvp()` นับ invite เก่าเป็น pending

**แผนแก้:**

| ขั้น | งาน | ไฟล์ |
| --- | --- | --- |
| 1 | ปุ่มยืนยันส่งคำเฉพาะ เช่น `ยืนยันปิดงาน` ไม่ใช่แค่ `ยืนยัน` | `lib/line*.ts`, webhook, UI แชท |
| 2 | Pre-pipeline ต้องเช็ค `last_intent === "confirm_*"` แล้ว step aside | `app/api/line/webhook/route.ts` |
| 3 | Pending state หมดอายุเมื่อ meeting จบ / ตอบแล้ว / ยกเลิกแล้ว | `lib/meetingInvite.ts`, settings keys |
| 4 | เพิ่ม regression test สำหรับ collision ก่อน deploy | `tests/` หรือ script ใน `scripts/` |
| 5 | UI แสดงบริบทชัด — "ยืนยันอะไร?" พร้อมปุ่มที่ผูก intent | v6 preview + `app/page.tsx` |

อ้างอิง checklist เต็ม: [`ai-assistant-online/AGENTS.md`](../ai-assistant-online/AGENTS.md)

### 2.2 สั่งงานได้เฉพาะแท็บแชท — ต้องสลับแท็บ (P1)

**ตัดสินใจแล้ว:** **ไม่** เปลี่ยนแท็บแรกเป็น "วันนี้" — คงโครง v5 คือ **ผู้ช่วย / ตาราง / งาน / ตั้งค่า** และเปิดแอปมาที่แท็บ **ผู้ช่วย** เหมือนเดิม

| ปัจจุบัน (v5) | ข้อเสีย | v6 ที่เสนอ |
| --- | --- | --- |
| แท็บแรก = แชท ✅ คงไว้ | อยู่หน้าตาราง/งานแล้วสั่งงานไม่ได้ | **แถบสั่งงานล่าง** ทุกหน้า → เปิด sheet ผู้ช่วย |
| Glance card ในแชท | ดีอยู่แล้ว — แสดงนัดถัดไป | **คง glance ในแท็บผู้ช่วย** ไม่แยกแท็บวันนี้ |
| สั่งงาน = ต้องอยู่แท็บแชท | — | sheet + chip บริบทตามแท็บที่เปิดอยู่ |

**ไม่ทำ:** แท็บ "วันนี้" แยก (แนว v3) — ผู้ใช้ต้องการเปิดมาแชทได้ทันที

### 2.3 โหมดโฟกัสแชท — sheet กินพื้ที่ แต่เนื้อหาแท็บบัง (P2)

เมื่อเปิด Assistant sheet แล้วผู้ใช้**ส่งข้อความ** (ไม่ใช่แค่เปิด sheet) ระบบเข้า **โหมดโฟกัสแชท**:

| ก่อนส่งข้อความ | หลังส่งข้อความแรก |
| --- | --- |
| sheet ~78% สูง, เห็น hero / timeline / งาน / chip ด้านหลัง | **ซ่อนเนื้อหาแท็บทั้งหมด** (นัด, timeline, งานเร่ง, ปุ่มลัด, รายการงาน, ตาราง, การ์ดตั้งค่า) |
| chip บริบทโผล่ด้านบน stream | **ซ่อน chip** — พื้นที่ให้ stream |
| หัวจอ + แท็บล่างยังเห็น | sheet **ขยาย ~92%** — เหลือแถบสั่งงาน + nav |

**กติกา**

- ทริกger: ส่งข้อความจากผู้ใช้ครั้งแรกใน session sheet (พิมพ์เอง, chip, หรือปุ่มลัดที่ส่งเข้าแชท)
- **ไม่** ซ่อนตอนแค่เปิด sheet — ยังเห็นภาพรวมงานด้านหลังได้จนกว่าจะเริ่มคุย
- ปุ่ม **"แสดงงาน"** ใน sheet → ออกจากโหมดโฟกัส เนื้อหาแท็บกลับมา (sheet ยังเปิดอยู่)
- ปิด sheet → ออกโหมดโฟกัส + แสดงเนื้อหาแท็บตามเดิม
- บน React: state `chatFocus: boolean` ใน `AssistantSheet.tsx` — ไม่ต้อง persist ข้าม session

**ไฟล์ที่เกี่ยวข้อง (ตอน implement):** `AssistantSheet.tsx`, `CommandBar.tsx`, `app/page.tsx`

### 2.4 Technical debt (P3)

| ปัญหา | ผลกระทบ | แนวทาง |
| --- | --- | --- |

| UI หลายชุด (`/`, `/mobile`, `/ai-office*`, `index.html`) | สับสนว่าอันไหน canonical | เก็บ `/` เป็นหลัก, deprecate static ที่ไม่ใช้ |

### 2.5 ฟีเจอร์ที่ผู้ใช้ถามบ่อย แต่ยังไม่มี (P3)

จาก `lib/notYet.ts` และ `docs/FEATURES.md`:

| หัวข้อ | สถานะ | แนวทางระยะสั้น |
| --- | --- | --- |

## 3. UX v6 — รายละเอียดการออกแบบ

### 3.1 โครงแท็บ (คง v5 — ไม่เปลี่ยนลำดับ)

```
[ ผู้ช่วย ]  [ ตาราง ]  [ งาน ]  [ ตั้งค่า ]
      ↑
  แท็บเริ่มต้น (เหมือน v5)
```

**แท็บ "ผู้ช่วย"** (แท็บแรก — คงเดิม):

1. **Glance card** — นัดถัดไป + เวลา + ปุ่ม "เตรียมนัด" (เหมือน v5)
2. **Stream แชท** — ประวัติสนทนา + ปุ่ม/slot/choice ในบับเบิล
3. **Chips คำสั่ง** — `/`, `/ตารางวันนี้`, …
4. **Composer** — ช่องพิมพ์ + ส่ง

**แถบสั่งงาน (ทุกหน้า — ใหม่ใน v6):**

- แถบลอยเหนือ nav bar: placeholder "พิมพ์สั่งงาน…" + ปุ่มส่ง
- ใช้จาก **แท็บตาราง / งาน / ตั้งค่า** โดยไม่ต้องสลับกลับผู้ช่วย
- แตะ → เปิด **Assistant sheet** (~78% สูง) — เนื้อหาแท็บยังเห็นด้านหลัง
- Context-aware chip ตามแท็บที่เปิดอยู่
- **หลังส่งข้อความ → โหมดโฟกัสแชท (P2):** ซ่อนเนื้อหาแท็บ + chip, sheet ขยาย ~92%

**แท็บอื่น:** ตาราง+ห้อง, งาน, ตั้งค่าบอร์ดการ์ด — คง v5

### 3.2 โหมดโฟกัสแชท (P2)

```
เปิด sheet          ส่งข้อความแรก              กด "แสดงงาน"
───────────         ────────────────           ──────────────
[ ตาราง / งาน ]     (ซ่อนทั้งหมด)             [ ตาราง / งาน ]
[ sheet 78%   ]  →  [ sheet 92%    ]      →    [ sheet 78%   ]
[ chip บริบท ]      (stream เต็ม)            [ chip กลับ ]
```

(แท็บผู้ช่วยมีแชทเต็มอยู่แล้ว — sheet ใช้หลักจากแท็บอื่น)

- เป้าหมาย: อ่านคำตอบยาว (สรุปประชุม, รายการนัด, digest ข่าว) โดยไม่ scroll สลับกับ hero/งาน
- เกณฑ์: stream แสดงได้ ≥ 5 บับเบิลบนจอ 390px โดยไม่ทับ composer

### 3.3 การยืนยันแบบปลอดภัย (UI)

เมื่อระบบต้องการยืนยัน:

```
┌─────────────────────────────────────┐
│ ⚠️ ปิดงานที่เลือก 3 รายการ?          │
│                                     │
│ • สรุปผล UAT                        │
│ • งบ IT Q4                          │
│ • สัญญา Cloud                       │
│                                     │
│ [ ยืนยันปิดงาน ]  [ ยกเลิก ]        │  ← ปุ่มส่งคำเฉพาะ ไม่ใช่ "ยืนยัน" ลอย ๆ
└─────────────────────────────────────┘
```

- ห้ามใช้ quick reply ที่ส่งแค่ "ยืนยัน" / "ok" โดยไม่มี prefix
- แสดงรายการที่จะเกิดขึ้นจริง (งาน/นัด/คน) ในบับเบิล

### 3.4 การแจ้งเตือน (เพิ่มใน SettingsBoard)

| การตั้งค่า | ค่าเริ่มต้น | หมายเหตุ |
| --- | --- | --- |
| เตือนก่อนประชุม | 15 นาที | push LINE + badge บน hero card |
| เตือนงานล่วงหน้า | 1 วัน | ยังไม่มีใน backend — ต้องเพิ่ม cron |
| เตือนงานเกินกำหนด | ทุกเช้า | มีอยู่แล้ว (`/api/reminders/run`) |

## 6. วิธีลอง v6 ก่อน implement

1. เปิด [`ux-v6-preview.html`](../ux-v6-preview.html) ใน Chrome / Edge / Safari
2. เปิดแอปมาที่แท็บ **ผู้ช่วย** (default เหมือน v5) — มี glance + แชทเต็ม
3. สลับไปแท็บ **ตาราง** หรือ **งาน** → แตะแถบ "พิมพ์สั่งงาน…" → sheet เปิดโดยไม่ต้องกลับแท็บผู้ช่วย
4. กดปุ่ม "ปิดงานที่เลือก" ในแท็บงาน → ดู dialog ยืนยันแบบคำเฉพาะ
5. ลอง chip บริบท ("เตรียมนัดนี้", "จองห้องนี้") บนหน้าต่าง ๆ
6. **ส่งข้อความใน sheet** → เนื้อหาแท็บ (นัด/งาน/ตาราง) หาย, sheet ขยาย — กด **"แสดงงาน"** เพื่อกลับ
