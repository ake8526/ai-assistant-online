อัปเดต: 13 ส.ค. 2026
สถานะ: **โค้ดทำเสร็จ + deploy ขึ้น Vercel แล้ว** เหลือขั้นเดียว — **deploy Cloudflare Worker**
(ต้องใช้บัญชี Cloudflare ของผู้ใช้ ดู [`cloudflare/README.md`](../cloudflare/README.md))
ถ้ายังไม่ deploy Worker: ระบบยังส่งได้ด้วยตัวสำรอง (Vercel/GitHub) แต่ **จะยังไม่ตรงเวลา**

| # | ความต้องการ | ความหมายที่ตกลงกัน |
|---|---|---|
| 1 | ข่าว **07:00** | ต้อง **ได้ข้อความบน LINE ตอน 07:00 เลย** ไม่ใช่ "เริ่มทำงานตอน 07:00" |

"สรุปประชุม" ในบริบทนี้ = ข้อความ `🌅 สรุปตารางเช้า` (agenda ของวัน) ไม่ใช่สรุป transcript ย้อนหลัง

## 2. อาการ + หลักฐานจริง

ข้อมูลจากตาราง `agent_traces` (Supabase) และ GitHub Actions API — ไม่ใช่การคาดเดา

### เวลาส่งจริง เช้า 13 ส.ค. 2026

| งาน | ตั้งไว้ | ทริกเกอร์จริง (เวลาไทย) | ส่งเสร็จ | ช้า |
|---|---|---|---|---|
| ข่าว (`/api/digest/push`) | 07:00 | **07:29:05** | ~07:30:43 | ~30 นาที |
| สรุปตาราง (`/api/brief/run?only=brief`) | 07:05 | **07:37:16** | 07:37:40 | ~32 นาที |

ห่างกัน **7 นาที** ตรงกับที่ผู้ใช้รายงาน

### ย้อนหลัง — trace แรกของแต่ละเช้า (UTC)

| วัน | trace แรก | = เวลาไทย |
|---|---|---|
| 13 ส.ค. | 00:29:05 | 07:29 |
| 12 ส.ค. | 00:29:05 | 07:29 |
| 11 ส.ค. | 00:24:26 | 07:24 |
| 10 ส.ค. | 00:24:26 | 07:24 |

→ สายประจำ ~25–30 นาที **ทุกวัน** ไม่ใช่เหตุสุดวิสัย

### GitHub Actions ที่ควรยิงทุก 5 นาที — ไม่ได้ยิงทุก 5 นาที

`cron.yml` ตั้ง `*/5 0 * * 1-5` (ควรได้ ~12 ครั้ง/ชม.) แต่รันจริง **12–17 ครั้ง/วัน** (≈ ชั่วโมงละครั้ง)

| วัน | จำนวน run จริง/วัน |
|---|---|
| 8 ส.ค. | 17 |
| 9 ส.ค. | 15 |
| 11 ส.ค. | 14 |
| 12 ส.ค. | 12 |

- run เช้ารอบแรกของทุกวันอยู่ที่ **00:37–00:45 UTC (07:37–07:45 ไทย)** — สายกว่า Vercel cron
- ทุก step จบใน **1 วินาที** = เจอ `skip (not due)` / `skip (sent)` แปลว่า **ไม่ได้เป็นตัวส่งจริงเลย**
- รอบ `50,55 23 * * 0-4` (06:50/06:55 ไทย) **ไม่เคยรันแม้ครั้งเดียว** ตลอด 131 run ที่ตรวจ

## 3. สาเหตุ (3 ชั้น)

### สาเหตุหลัก — Vercel Cron บนแพลน Hobby ไม่ตรงนาทีโดยดีไซน์
`vercel.json` ตั้ง:
```json
{ "path": "/api/digest/push",            "schedule": "0 0 * * 1-5" }   // = 07:00 ไทย
{ "path": "/api/brief/run?only=brief",   "schedule": "5 0 * * 1-5" }   // = 07:05 ไทย
```
แพลน Hobby รับประกันเพียง *"ยิงภายใน 1 ชั่วโมงของเวลาที่ตั้ง"* ไม่ใช่ตรงนาที Vercel เลือก offset เอง
และของโปรเจกต์นี้ล็อกอยู่ที่ **+25 ถึง +32 นาที** → กลายเป็น 07:29 / 07:37 ทุกวัน

### สาเหตุที่สอง — ตัวที่ควรกู้ความตรงเวลา (GitHub Actions) ถูก throttle
GitHub deprioritize/ดรอป scheduled run ความถี่สูงบน runner ฟรี `*/5` จึงเหลือ ~1 ครั้ง/ชม.
เป็นข้อจำกัดของแพลตฟอร์ม **ไม่ใช่บั๊กในโค้ด** → พึ่งพาเป็นตัวส่งหลักไม่ได้

### สาเหตุที่สาม — ช่องว่าง 7 นาที เกิดจากโครงสร้าง cron
เป็น cron แยกกัน 2 ตัว ตั้งห่าง 5 นาที + jitter ของแต่ละตัว → ได้ 7–8 นาที
(โค้ดมีโหมด `only=both` ที่ส่งข่าวแล้วต่อด้วยตารางใน invocation เดียวอยู่แล้ว แต่ cron ไม่ได้เรียกใช้)

### ปัจจัยเสริม — สถาปัตยกรรมเป็น "ยิงแล้วค่อยสร้าง"
สร้าง digest ใช้ ~100 วินาที (NewsData → อ่านบทความ → Gemini ต่อเรื่อง)
วัดจาก trace 13 ส.ค.: `เริ่มรวบรวมข่าว 07:29:05` → `สรุปเสร็จ 07:30:43`
**แม้ทริกเกอร์ตรง 07:00 เป๊ะ ข้อความก็จะถึงจริง ~07:02** → เป้า "07:00 เลย" ทำไม่ได้ถ้าไม่แยกขั้นสร้างออกมา

## 4. สิ่งที่ทำจริง — แยก "สร้าง" ออกจาก "ส่ง"

### หลักการ
Worker **ไม่รู้** ว่าใครตั้งกี่โมง (ผู้ใช้ 4 คนตั้งไม่เหมือนกัน มีคนตั้ง 06:00) มันแค่
**เคาะทุกนาที** ในช่วงเช้า แล้วฝั่ง Vercel เป็นคนตัดสินจาก `settings` ของแต่ละคน
→ ผู้ใช้เปลี่ยนเวลาในแอปได้เองโดยไม่ต้องแก้ Worker

### ไทม์ไลน์ (ยกตัวอย่างคนที่ตั้งข่าว 07:00)

| เวลา | งาน | ใช้เวลา |
|---|---|---|
| 06:48–06:56 | `prewarm?stage=auto` เห็นว่าข่าวเหลือ 4–12 นาที → **build + cache** (ไม่ส่ง) รอบถัดไปเจอ cache แล้วข้าม | ~100 วิ |
| 06:58–07:00 | `prewarm?stage=auto` เห็นว่าตารางเหลือ 1–3 นาที → build agenda (สร้างใหม่ทุกรอบ ปฏิทินสดที่สุด) | ~5 วิ |
| **07:00:00** | `brief/run?only=both` → ข่าวถึงเวลา → **push จาก cache** | ~2–4 วิ (วัดจริง) |
| **07:01:00** | รอบถัดไป → ตารางถึงเวลา → push agenda ที่เตรียมไว้ | ~2–4 วิ (วัดจริง) |

fallback: ถ้า prewarm ล่มทุกรอบ → ตอนส่งจะ build สดให้ (ช้าแต่ไม่เงียบหาย)

### ไฟล์/จุดที่แก้

| จุด | เดิม | ใหม่ |
|---|---|---|
| `cloudflare/` *(ใหม่)* | — | Worker cron `* * * * *` → เช้าเคาะทุกนาที (05:30–08:20), กลางวันทุก 5 นาที |
| `lib/morningCache.ts` *(ใหม่)* | — | cache ข่าว/agenda ที่เตรียมไว้ (ผูกกับวันที่ไทย, อายุไม่เกิน 90 นาที, ล้างทันทีที่ส่งสำเร็จ) |
| `app/api/morning/prewarm/` *(ใหม่)* | — | `stage=auto` เตรียมของตามเวลาของแต่ละคน · `explain=1` ดูตารางที่ระบบคำนวณได้ · `wait=1` รอผลตอนทดสอบ |
| `NOTIFY_DEFAULTS` | brief 07:00 / news 07:00 | news 07:00 / **brief 07:01** |
| `notifyConfigFromSettings` | — | **ถ้าเก็บเวลาไว้เท่ากัน → เลื่อน brief +1 นาทีอัตโนมัติ** (07:00→07:01, 06:00→06:01) จึงไม่ต้องไปแก้ค่าที่ผู้ใช้ตั้งไว้ และ UI เขียนทับเท่ากันอีกก็ยังถูก |
| `NOTIFY_EARLY_SLACK_MIN` | 5 (ส่งก่อนเวลาได้) | **0** — เวลาที่ตั้ง = เวลาที่ต้องถึงมือ |
| `*_last_sent` | เก็บแค่ `2026-08-13` | เก็บ timestamp ไทย `2026-08-13T07:00:01+07:00` |
| brief/news เช็คเวลาอิสระ | ต่างคนต่างเช็ค | brief ต้องรอ **ข่าวส่งจริงแล้ว** (+ผ่อนผัน 15 นาที กันข่าวล่มแล้วตารางไม่ออก) |
| อ่าน settings | 7 query/คน/รอบ | **1 query** (`getSettingsFor`) — จำเป็นเพราะเช้านี้เคาะทุกนาที |
| `.github/workflows/cron.yml` | `*/5` 3 รอบ | ตัวสำรอง `*/10` (ตัดรอบ 23:50/55 ที่ไม่เคยรัน) |
| `vercel.json` | ข่าว 07:00 + ตาราง 07:05 | ตัวสำรอง: prewarm รอบเช้า + `only=both` |

### ความแม่นที่วัดได้จริง (13 ส.ค. 2026, ทดสอบส่งเข้า LINE จริง)

| รายการ | เวลา |
|---|---|
| รอบเช็คเปล่า ๆ ทั้ง 4 คน (ไม่มีใครถึงเวลา) | 1.1–2.9 วิ |
| ส่งข่าวจาก cache | ~4–7 วิ (รอบแรกมี cold start) |
| ส่งสรุปตารางจาก cache | ~4 วิ |
| สร้างข่าวจริง (prewarm) | 26–28 วิ |

→ ข้อความจะถึง **07:00:0x** (วินาทีหลักหน่วย) ไม่ใช่ 07:00:00.000
เพดานที่เลี่ยงไม่ได้: cold start ของ Vercel function + Supabase round trips + LINE API (~300–800 ms)
LINE แสดงเวลาเป็น `07:00` และสรุปประชุมเป็น `07:01` ตามเป้า
เดิมรอบเช็คใช้ 4–6 วิ เพราะเช็คทีละคนแล้วยิง query ซ้ำ → เปลี่ยนเป็น query เดียวทุกคน (`dueNowForUsers`)

### การเฝ้าระวัง
`/api/morning/punctuality` (Worker เรียก 08:30 ทุกวัน) เทียบ `*_last_sent` กับเวลาที่ตั้งไว้
ของแต่ละคน ถ้าช้าเกิน 5 นาทีหรือไม่ส่งเลย → แจ้งผู้ดูแลทาง LINE ครั้งเดียวต่อวัน
(ผู้รับ: `settings _ops/punctuality_admin` → ตั้งเป็น weerasak.pi ไว้แล้ว) · `?dry=1` = ดูรายงานเฉย ๆ

## 7. วิธีตรวจหลักฐานซ้ำ

trace แรกของเช้า (แทน `<DATE>` ด้วยวันที่, เวลาเป็น UTC — ไทย = +7):

```bash
curl -sS -H "apikey: $SUPABASE_SERVICE_KEY" -H "Authorization: Bearer $SUPABASE_SERVICE_KEY" "$NEXT_PUBLIC_SUPABASE_URL/rest/v1/agent_traces?select=created_at,step,label&created_at=gte.<DATE>T00:00:00Z&created_at=lt.<DATE>T01:10:00Z&order=created_at.asc&limit=5"
```

เวลารันจริงของ GitHub Actions (repo เป็น public ไม่ต้อง auth):

```bash
curl -sS "https://api.github.com/repos/ake8526/ai-assistant-online/actions/workflows/cron.yml/runs?per_page=100"
```

ตารางที่ระบบคำนวณได้ตอนนี้ของทุกคน (ไม่ส่งอะไร ไม่แก้อะไร):

```bash
curl -sS -X POST -H "x-cron-secret: $CRON_SECRET" "https://ktis-ai-assistant.vercel.app/api/morning/prewarm?explain=1"
```
